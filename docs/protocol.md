# 智慧云马桶 BLE 协议（逆向自小程序 `wxf105815db957545f`）

## 1. 传输层

- 蓝牙广播名：`Intelligence bidet`（小程序 `globalData.bleStipulateName`）
- GATT 服务/特征值 UUID **未硬编码**，小程序的做法是：
  1. `createBLEConnection` → `getBLEDeviceServices`
  2. 遍历所有 `isPrimary` 服务 → `getBLEDeviceCharacteristics`
  3. 属性含 `write` 的特征值作为下行通道；属性含 `notify` / `indicate` 的特征值全部开启订阅
  4. 属性含 `read` 的特征值做一次读取
- 连接建立后立即下行握手：`AT+CMD=BLECONNECTOK#`（20 字节，ASCII）
- 设备回 `AT+CMD=OK#` 表示链路就绪

### 写入行为的源码事实（`app-service.js`）

| 事实 | 源码依据 |
| --- | --- |
| 全工程只有 2 处写：`writeStringDataToBLE`（握手专用）与 `writeUint8DataToBLE`（发命令帧） | `wx.writeBLECharacteristicValue` 仅出现在 `3179` / `3160` 两个函数内 |
| 握手只在发现可写特征值时发**一次**，且紧接着才开启 notify 订阅 | `2937`，`o.properties.write && (... writeStringDataToBLE("AT+CMD=BLECONNECTOK"), ...)` 与同行的 `notifyBLECharacteristicValueChange` |
| 没有周期写、没有心跳、没有轮询 | 命令表组 0（状态查询 `0x81/0xC8`）在页面代码中**调用 0 次**；`parseInquireSendDataToBLE` / `parseInquireSendDataToProbBLE` 也**调用 0 次**（死码） |
| 未协商 MTU、未指定 writeType | 全文无 `setBLEMTU`、无 `writeType` 参数，走微信默认（带响应写） |

结论：设备被设计成「连上时被告知一次，之后纯推送」。插件因此也只在每条连接上握手一次，保活仅用命令表内的状态查询帧（静默 8 秒才发），其余交给快速重连。


## 2. 帧格式

下行（App → 马桶）：

```
"AT+UART=" (8 字节 ASCII) + payload(8 字节) + 0x01 + 0x23('#')
```

`payload` 结构：

| 偏移 | 值 | 含义 |
| --- | --- | --- |
| 0 | `0xA5` | 帧头 |
| 1 | `0xFA` | 帧头 |
| 2 | `0x00` | 方向（下行） |
| 3 | cmd0 | 命令域（一般 `0x81`，时间设置 `0x79/0x80`，语音 `0xA0`） |
| 4 | cmd1 | 命令码 |
| 5 | `0x00` | 保留（时间设置时不用） |
| 6 | checksum | `~(payload[0..5] 之和) & 0xFF` |
| 7 | `0xFB` | 帧尾 |

上行（马桶 → App），ASCII 头相同，按 `payload[2]` 区分三类：

| 类型 | payload 长度 | 结构 | 校验 |
| --- | --- | --- | --- |
| 状态快照 | 16 | `A5 FA 01 d0..d10 chk FB` | `d[14] == ~sum(d[0..13]) & 0xFF` |
| 事件 / 应答 | 8 | `A5 FA 00 03 code 00 chk FB` | `d[6] == ~sum(d[0..5]) & 0xFF` |
| 语音状态 | 8 | `A5 FA 00 A1 on level chk FB` | `d[6] == sum(d[0..5]) & 0xFF`（注意是**正常和**，不取反） |

> 小程序只在收到 `#`（`0x23`）时认为一帧结束，缓冲区内 `...OK#` 也会被当作握手结束。

## 6. 需要注意的源码细节

- 「感距」滑条的映射是 `settingButtonIndex 22..27 → 组 6 索引 15..20`，即 `0x81/0x1D` 与 `0x81/0x22..0x26`。**0% 与「关自动翻盖」共用 `0x1D`**（关闭感距等于关掉人来自动翻盖），厂商有意如此；插件按原样实现成 `select.感距`。
- 「自动翻盖」开关状态没有独立回读位，小程序用「感距档 1..14」间接表示，插件沿用该推导。
- 命令表里还有 4 个码从未被任何页面调用（死码），插件未实现：`0x81/0x86`、`0x81/0x87`（自动冲水组）、`0x81/0x45`（灯圈组）、`0xA0/0x03`（语音组）。
- 状态查询命令 `0x81/0xC8` 在小程序里从未被调用，设备完全主动推送；插件同样不发周期写入。
